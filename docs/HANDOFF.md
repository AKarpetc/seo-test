## Что это за проект

Программатик-SEO на открытых данных правительства США. Одна страница на запись,
статическая выкладка на Cloudflare Pages.

**Цель пересматривалась дважды, текущая формулировка:** окупить инфраструктуру
и проверить, есть ли спрос. Владелец **не готов заниматься продажами** — ни звонков,
ни писем. Это решение принято осознанно и пересматривать его не нужно.

Следствие: B2B-направления (продажа данных о перевозчиках и новых компаниях)
построены, но **не запускаются**. Остаётся только SEO с рекламной монетизацией.

`snowSeasons` (сколько зим наблюдалось) и `snowySeasons` (в скольких был снег).

«снег редок: X из Y зим».

Станция для снега у ZIP **своя**, `ZipClimate.snowStationId`, и часто не та,
что для заморозков. Причина в данных, см. «грабли».

## Что осталось — по владельцу

0. **DNS для stormsthathit.com.** Домен привязан к проекту Pages, но записей
   в зоне нет: токен агента не имеет прав на DNS. В панели Cloudflare → домен
   `stormsthathit.com` → DNS → добавить две записи CNAME, обе с прокси:
   `@` → `storms-that-hit.pages.dev` и `www` → `storms-that-hit.pages.dev`.
   Либо Workers & Pages → `storms-that-hit` → Custom domains — там Cloudflare
   предложит создать записи сам. После этого сертификат выпустится за минуты.
   Затем Search Console: добавить ресурс типа Domain и отправить
   `https://stormsthathit.com/sitemap.xml`.

1. **Залить репозиторий на GitHub.** Remote уже добавлен
   (`git@github.com:AKarpetc/seo-test.git`), ветка `main`, репозиторий на GitHub
   создан и пуст, SSH-ключ работает. История проверена на секреты — чисто.
   Осталась одна команда:
   ```
   git push -u origin main
   ```
   Агент её выполнить не может: отправка содержимого репозитория наружу
   блокируется политикой среды. `gh auth login` тоже не подходит — нужен браузер.

   В рабочем дереве есть незакоммиченные изменения, см. «Обвязка OpenNext» ниже.

2. ~~**Search Console**~~ — сделано 14.09.2026. Оба домена подтверждены, sitemap отправлены.
   **Bing Webmaster Tools** — по желанию: импорт из Search Console, вход тем же
   Google-аккаунтом. Даёт 3–5% трафика, плюс индекс Bing питает ChatGPT Search
   и Copilot. IndexNow уже подключён и от Bing Webmaster Tools не зависит.
   Дальше **не трогать 3–4 недели**: на новом домене краулинговый бюджет выдаётся
   медленно, повторная отправка sitemap ничего не ускоряет.

3. **Ротировать ключ AWS** — у текущего права `ec2:*`, `rds:*`, `iam:CreateRole`.
   Завести отдельный ETL-ключ только на `s3:*` по бакетам `seo-pr-*`.

4. **Подготовка к доходу — сделано 14.09.2026, кроме заявки.** На сайтах появились
   `/about`, `/contact`, `/privacy`. Код аналитики и рекламы написан и встроен,
   но **выключен** — включается переменными окружения, без правок кода:

   | Переменная | Откуда взять | Что включает |
   |---|---|---|
   | ~~`NEXT_PUBLIC_CF_BEACON_TOKEN`~~ | не понадобилась, см. ниже | свой счётчик |
   | `NEXT_PUBLIC_ANALYTICS_ENABLED` | **уже `1`** | раздел про аналитику в политике |
   | `NEXT_PUBLIC_ADSENSE_CLIENT` | AdSense после одобрения, вид `ca-pub-…` | скрипт рекламы |
   | `NEXT_PUBLIC_ADSENSE_SLOT_TOP` / `_BOTTOM` | AdSense, рекламные блоки | два места на странице |
   | `NEXT_PUBLIC_CONTACT_EMAIL` | ваш публичный адрес | контакты на `/contact` и в политике |

   Заполнить в `.env`, затем `npm run publish -- frost` и `-- recalls`.
   **Рабочую почту сюда не ставить** — адрес публикуется на сайте.

   Заявку в AdSense подавать **в декабре**, см. событие в календаре.

   **Аналитика включена 14.09.2026** через встроенную кнопку Cloudflare Pages:
   проект → вкладка Metrics → Web Analytics → Enable. Cloudflare сам вставляет
   счётчик на границе сети, своего кода не нужно, `NEXT_PUBLIC_CF_BEACON_TOKEN`
   остаётся пустым. Проверено на живых доменах: `beacon.min.js` присутствует
   ровно один раз на обоих сайтах.

   Отсюда важное разделение, которое легко сломать: **факт «аналитика работает»
   и способ её вставки — разные вещи.** Раздел про аналитику в политике
   конфиденциальности управляется `NEXT_PUBLIC_ANALYTICS_ENABLED`, а не наличием
   токена. Сначала было завязано на токен — счётчик работал, а политика о нём
   молчала. Если когда-нибудь перейдёте на свой счётчик, **не включайте оба**:
   получится двойной подсчёт.

5. **Токен Cloudflare** лежит в `.env` как `CLOUDFLARE_API_TOKEN`, права `Pages: Edit`.
   Перечислять аккаунты он не умеет, и это осознанно — минимальные права. Следствие
   описано в «граблях».

6. **Опционально:** ключи USPTO и FCC. USPTO требует верификации через ID.me,
   которая для резидента Казахстана скорее всего недоступна. Потеря небольшая.

## Решения, которые НЕ надо пересматривать

- **Не публиковать 12 млн страниц справочников.** Это ровно тот паттерн, который
  политика Google scaled content abuse называет и обнуляет.
- **Не брать десятки доменов.** Новый домен зреет 4–8 месяцев; в одиночку
  реально вести 2–3 SEO-сайта.
- **Не разносить одну тему по двум доменам.** ZIP-страницы и страницы по станциям
  отвечают на один вопрос — они на одном домене, лишнее отфильтровано по населению.
- **Не разворачивать EC2.** Шаблоны в `infra/` валидны, но при статике сервер не нужен.
  Стоимость упала с ~$50/мес до цены домена.
- **Не заниматься B2B-продажами.** Владелец отказался.
- **Обвязка OpenNext — отложена, откатывать не нужно.** 14.09.2026 `npx wrangler`
  сам развернул мастер `@opennextjs/cloudflare`: он обслуживает деплой Next.js
  как воркера, то есть отвергнутый серверный путь. `open-next.config.ts`
  и `wrangler.jsonc` убраны в `_unused/opennext-scaffold/`, там же README
  с подробностями. Правки в `next.config.ts`, `package.json`, `package-lock.json`
  и `.gitignore` оставлены как есть — сознательно. Проверено: `npm run build`
  проходит, `npm run publish` выкладывает штатно.
  `public/_headers` намеренно оставлен в проекте — он полезен и уже выложен.

## Грабли, на которые уже наступали

Все исправлены, но при работе с этими источниками они вернутся:

| Источник | Подвох |
|---|---|
| FAA | отдаёт 403 без браузерного User-Agent |
| NHTSA | «отзывов нет» приходит как HTTP **400** с валидным пустым телом |
| NOAA | даты заморозков — строки `MM/DD`, не день года |
| FDIC | переехал на `api.fdic.gov`; `locations` даёт 78k отделений, `institutions` — 4.5k |
| USPTO | `bulkdata.uspto.gov` больше не резолвится |
| Census | без ключа отдаёт `missing_key.html`, `www2.census.gov` блокирует по UA |
| USDA зоны | **нельзя** вывести из средней минимальной температуры NOAA — только `phzmapi.org` |
| Socrata | `$where` по датам, сквозная пагинация ограничена |
| NHTSA | при 6 параллельных запросах через ~500 вызовов начинает отдавать **403** — это троттлинг, не бан. Загрузчики ждут 15 с × попытка; ходить с `CONCURRENCY=3–4` |
| NHTSA ratings | до 2011 года `OverallRating` = «Not Rated», звёзды лежат в `FrontCrashDriversideRating` / `SideCrashDriversideRating` |
| GHCN-daily | у части наблюдателей `SNOW` пишется нулём при 40" нормы (Lower St Anthony Falls в Миннеаполисе: 8 снежных зим из 20). Аэропортовые ASOS-станции (DEN, LAX) элемента `SNOW` не имеют вовсе |

**Станция для снега подбирается отдельно** (`assignSnowStations` в `scripts/load_snow.ts`):
доверяются станции, где есть дата снега, либо «редко» подтверждено мягким
январём (`avgLowJan ≥ 33°F`) или нормой снега < 5". Среди доверенных берётся
ближайшая в 40 милях, штраф за пропущенные зимы `(1 − доля снежных) × 40 миль`,
своей frost-станции даётся фора 3 мили. Пересчёт без скачивания архива:
`SNOW_ASSIGN_ONLY=1 npm run load:snow`. Средняя дистанция 7,7 мили, 90-й процентиль 14,5.

**Кэш `unstable_cache` переживает `next build`.** Списки марок и моделей
для хабов кэшируются на сутки в `.next/cache`; после догрузки новых марок
47 хабов марок и 721 хаб моделей отдавали 404 при рендере статики.
`publish-site.sh` теперь делает `rm -rf .next/cache` перед сборкой. Если
рендерите вручную — тоже.

Хелпер `toInt` раньше срезал точку и превращал `"204.0"` в `2040` — исправлено
в `scripts/lib/etl.ts`, но при добавлении источников стоит проверять значения глазами,
а не только факт парсинга.

**IndexNow подключён к `npm run publish`** (14.09.2026). Ключ в `.env` как
`INDEXNOW_KEY`, он **публичный по устройству протокола** — отдаётся с каждого домена
по адресу `/<ключ>.txt`. Файл ключа пишется в `static/<секция>/` до подсчёта файлов
и уезжает вместе с сайтом.

Отправляются **только изменившиеся страницы**: `scripts/ops/indexnow.ts` держит
манифест хешей в `logs/indexnow-<секция>.json` и сравнивает с ним. Слать 18 тысяч
неизменившихся URL при каждой выкладке бессмысленно и ведёт к игнорированию ключа.
Манифест локальный, в git не попадает — на новой машине первая выкладка отправит всё
заново. Партии по 10 000, это предел протокола.

Подвох: сразу после первой выкладки ключа приходит `403 SiteVerificationNotCompleted` —
IndexNow ещё не успел забрать файл. У нас проверка заняла **от 5 до 8 минут**. Это не
ошибка настройки, надо просто повторить. Неудачный пинг **намеренно не роняет выкладку**:
сайт уже выложен, и откатывать его из-за пинга неправильно. Манифест при неудаче
не пишется, поэтому повтор отправит всё.

**Первая отправка выполнена 14.09.2026:** 18 686 + 13 918 = 32 604 URL, HTTP 200.
После добавления общих страниц и правок шаблона объём вырос до 18 689 + 13 921 = 32 610.
Правка шаблона меняет каждую страницу, поэтому такая выкладка честно отправляет всё
заново — это не ошибка определения изменений.

**Статическая выкладка:** домен зашивается на этапе сборки (canonical и название сайта
попадают в HTML). Сборка с чужим origin = 18 686 страниц со ссылками на чужой домен.
`npm run publish` выставляет всё сам.

**`unstable_cache` хранит значение как JSON.** `Map` этого не переживает и со второго
вызова возвращается пустым объектом — первый запрос проходит на промахе кэша и
выглядит рабочим, следующий падает с `(intermediate value).get is not a function`.
В `src/lib/recalls.ts` кэшируются массивы, `Map` строится после. При добавлении
кэшированных справочников проверять **двумя запросами подряд**, не одним.

**Шаблон.** Цвет задан семантическими токенами в `src/app/globals.css`, тёмная тема
описана там один раз. Не возвращать классы вида `slate-600` в компоненты: они
не переключаются вместе с темой. Контраст всех сочетаний проверен по WCAG AA;
при смене палитры перепроверять, `--fg-faint` уже один раз не проходил (3.85:1).

**Раскладка файлов и слэш.** Страницы пишутся как `путь.html`, а не `путь/index.html`.
Второй вариант Cloudflare Pages отдаёт только по адресу со слэшем, а canonical
и sitemap объявляют адрес без слэша — получался `308` на каждой из 25 340 страниц.
Исправлено в `scripts/build_static_site.ts`, функция `outputFile`. Если будете её
трогать — проверьте `curl -o /dev/null -w '%{http_code} %{redirect_url}'`, там должен
быть `200` без редиректа.

**Токен Cloudflare без права перечислять аккаунты.** Для **несуществующего** проекта
wrangler уходит на новый путь («Delegating to the latest version of Cloudflare Pages,
now part of Cloudflare Workers»), а тот требует перечисления аккаунтов и падает
с `user account fetch permission denied`. Сообщение обманчивое: настоящая ошибка
приходит из обработчика ошибок и маскирует причину. Лечится тем, что проект должен
уже существовать — создать его через REST API:
`POST /accounts/{id}/pages/projects` с `{"name":..., "production_branch":"main"}`.
Тогда wrangler остаётся на классическом пути, где хватает `Pages: Edit`.

**Новый дашборд Cloudflare не показывает классические проекты Pages** в разделе
Compute → Workers & Pages: там пусто. Открывать напрямую:
`https://dash.cloudflare.com/<account_id>/pages/view/<project-name>`.

**Search Console, ресурс типа Domain.** В поле отправки sitemap нужен полный адрес
`https://frostdatefinder.com/sitemap.xml`, а не короткий путь `sitemap.xml`: короткая
форма работает только у ресурсов типа URL prefix, где префикс уже задан. Иначе
форма отвечает «Недопустимый адрес файл Sitemap». Тип Domain выбран сознательно —
он покрывает апекс и `www` одним ресурсом, а `www` у нас отдаёт копию сайта.

**Ускорить индексацию нельзя ничем**, в том числе через API. Indexing API Google
разрешает только для `JobPosting` и `BroadcastEvent`; для обычных страниц он
игнорируется и нарушает условия. Search Console API полезен для чтения данных
и для автоматизации следующих сайтов, но не для скорости обхода.

```
npm run status                    # что загружено, и что реально отдают живые сайты
npm run indexnow -- --dir static/frost --host frostdatefinder.com --dry-run

npm run publish -- storms         # выложить stormsthathit.com

RECALL_MAKES=specialty RECALL_CONCURRENCY=4 npm run load:recalls   # RV, мото, прицепы
COMPLAINT_CONCURRENCY=4 npm run load:complaints                    # жалобы + рейтинги (~1,5 ч)
RATINGS_ONLY=1 npm run load:complaints                             # только машины без звёзд
```
