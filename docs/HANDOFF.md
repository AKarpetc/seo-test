# Состояние проекта — передача в новую сессию

Обновлено 14.09.2026, после выкладки.

---

## Что это за проект

Программатик-SEO на открытых данных правительства США. Одна страница на запись,
статическая выкладка на Cloudflare Pages.

**Цель пересматривалась дважды, текущая формулировка:** окупить инфраструктуру
и проверить, есть ли спрос. Владелец **не готов заниматься продажами** — ни звонков,
ни писем. Это решение принято осознанно и пересматривать его не нужно.

Следствие: B2B-направления (продажа данных о перевозчиках и новых компаниях)
построены, но **не запускаются**. Остаётся только SEO с рекламной монетизацией.

## Что осталось — по агенту

Ничего блокирующего. Возможные следующие шаги, по убыванию ценности:

~~Качество воды~~ и ~~риск затопления~~ **проверены 14.09.2026 и отклонены** —
разбор в [КУДА_РАСШИРЯТЬСЯ.md](КУДА_РАСШИРЯТЬСЯ.md). Коротко: воду уже сделал

а автодополнение показывает, что запрос туристический. У затопления зоны
не совпадают с границами ZIP, то есть точную страницу собрать нельзя, и выдачу
держат страховщики.

**Правило, выведенное из этих проверок:** ниша живёт, если рядом с запросом
никто не продаёт дорогой товар. Фильтр за $300–2000 и полис за $500–3000 в год
окупают посетителя в десятки раз лучше рекламы. Проверять выдачу и продавцов
**до** того, как смотреть на данные.

~~Актёры на Apify~~ и ~~приливы~~ **тоже проверены 14.09.2026 и отклонены.**

Apify: $470 — это среднее, а не медиана, как было записано у нас; распределение
степенное, у большинства актёров 0–5 пользователей. Актёров по FMCSA больше
десяти на том же открытом Socrata-API, лидер собрал 15 пользователей в месяц,
цены уже уронили в 500 раз. По реестрам компаний семь конкурентов, у одного
покрытие включает наши штаты. Отдельно не выяснено, доходят ли выплаты
в Казахстан — PayPal там исторически не принимает входящие.

Приливы: фильтр по деньгам проходит, но incumbent четыре — `tide-forecast.com`,
`usharbors.com`, `tidetime.org`, `tideschart.com`.

**Итог дня: 0 из 4.** Вывод не про ниши, а про стратегию — у открытых данных
нет рва. Есть коммерческая ценность — там уже стоит продавец, который окупает
посетителя в десятки раз лучше рекламы. Нет продавца — обычно потому, что тема
мало кому нужна. Заморозки работают именно поэтому: продать садоводу нечего.

**Что делать вместо четвёртой ниши.** Углубить отзывы авто на уже загруженных

## Решения, которые НЕ надо пересматривать

- **Не публиковать 12 млн страниц справочников.** Это ровно тот паттерн, который
  политика Google scaled content abuse называет и обнуляет.
- **Не брать десятки доменов.** Новый домен зреет 4–8 месяцев; в одиночку
  реально вести 2–3 SEO-сайта.
- **Не разносить одну тему по двум доменам.** ZIP-страницы и страницы по станциям
  отвечают на один вопрос — они на одном домене, лишнее отфильтровано по населению.
- **Не разворачивать EC2.** Шаблоны в `infra/` валидны, но при статике сервер не нужен.
  Стоимость упала с ~$50/мес до цены домена.
- **Не заниматься B2B-продажами.** Владелец отказался.
- **Обвязка OpenNext — отложена, откатывать не нужно.** 14.09.2026 `npx wrangler`
  сам развернул мастер `@opennextjs/cloudflare`: он обслуживает деплой Next.js
  как воркера, то есть отвергнутый серверный путь. `open-next.config.ts`
  и `wrangler.jsonc` убраны в `_unused/opennext-scaffold/`, там же README
  с подробностями. Правки в `next.config.ts`, `package.json`, `package-lock.json`
  и `.gitignore` оставлены как есть — сознательно. Проверено: `npm run build`
  проходит, `npm run publish` выкладывает штатно.
  `public/_headers` намеренно оставлен в проекте — он полезен и уже выложен.

## Грабли, на которые уже наступали

Все исправлены, но при работе с этими источниками они вернутся:

| Источник | Подвох |
|---|---|
| FAA | отдаёт 403 без браузерного User-Agent |
| NHTSA | «отзывов нет» приходит как HTTP **400** с валидным пустым телом |
| NOAA | даты заморозков — строки `MM/DD`, не день года |
| FDIC | переехал на `api.fdic.gov`; `locations` даёт 78k отделений, `institutions` — 4.5k |
| USPTO | `bulkdata.uspto.gov` больше не резолвится |
| Census | без ключа отдаёт `missing_key.html`, `www2.census.gov` блокирует по UA |
| USDA зоны | **нельзя** вывести из средней минимальной температуры NOAA — только `phzmapi.org` |
| Socrata | `$where` по датам, сквозная пагинация ограничена |

Хелпер `toInt` раньше срезал точку и превращал `"204.0"` в `2040` — исправлено
в `scripts/lib/etl.ts`, но при добавлении источников стоит проверять значения глазами,
а не только факт парсинга.

**Статическая выкладка:** домен зашивается на этапе сборки (canonical и название сайта
попадают в HTML). Сборка с чужим origin = 18 686 страниц со ссылками на чужой домен.
`npm run publish` выставляет всё сам.

**`unstable_cache` хранит значение как JSON.** `Map` этого не переживает и со второго
вызова возвращается пустым объектом — первый запрос проходит на промахе кэша и
выглядит рабочим, следующий падает с `(intermediate value).get is not a function`.
В `src/lib/recalls.ts` кэшируются массивы, `Map` строится после. При добавлении
кэшированных справочников проверять **двумя запросами подряд**, не одним.

**Шаблон.** Цвет задан семантическими токенами в `src/app/globals.css`, тёмная тема
описана там один раз. Не возвращать классы вида `slate-600` в компоненты: они
не переключаются вместе с темой. Контраст всех сочетаний проверен по WCAG AA;
при смене палитры перепроверять, `--fg-faint` уже один раз не проходил (3.85:1).

**Раскладка файлов и слэш.** Страницы пишутся как `путь.html`, а не `путь/index.html`.
Второй вариант Cloudflare Pages отдаёт только по адресу со слэшем, а canonical
и sitemap объявляют адрес без слэша — получался `308` на каждой из 25 340 страниц.
Исправлено в `scripts/build_static_site.ts`, функция `outputFile`. Если будете её
трогать — проверьте `curl -o /dev/null -w '%{http_code} %{redirect_url}'`, там должен
быть `200` без редиректа.

**Токен Cloudflare без права перечислять аккаунты.** Для **несуществующего** проекта
wrangler уходит на новый путь («Delegating to the latest version of Cloudflare Pages,
now part of Cloudflare Workers»), а тот требует перечисления аккаунтов и падает
с `user account fetch permission denied`. Сообщение обманчивое: настоящая ошибка
приходит из обработчика ошибок и маскирует причину. Лечится тем, что проект должен
уже существовать — создать его через REST API:
`POST /accounts/{id}/pages/projects` с `{"name":..., "production_branch":"main"}`.
Тогда wrangler остаётся на классическом пути, где хватает `Pages: Edit`.

**Новый дашборд Cloudflare не показывает классические проекты Pages** в разделе
Compute → Workers & Pages: там пусто. Открывать напрямую:
`https://dash.cloudflare.com/<account_id>/pages/view/<project-name>`.

**Search Console, ресурс типа Domain.** В поле отправки sitemap нужен полный адрес
`https://frostdatefinder.com/sitemap.xml`, а не короткий путь `sitemap.xml`: короткая
форма работает только у ресурсов типа URL prefix, где префикс уже задан. Иначе
форма отвечает «Недопустимый адрес файл Sitemap». Тип Domain выбран сознательно —
он покрывает апекс и `www` одним ресурсом, а `www` у нас отдаёт копию сайта.

**Ускорить индексацию нельзя ничем**, в том числе через API. Indexing API Google
разрешает только для `JobPosting` и `BroadcastEvent`; для обычных страниц он
игнорируется и нарушает условия. Search Console API полезен для чтения данных
и для автоматизации следующих сайтов, но не для скорости обхода.

## Честный прогноз

Октябрь–декабрь — индексация, доход $0. Февраль–апрель — сезон заморозков,
15–60 тыс. визитов, $120–500/мес. Окупаемость домена ($1.33/мес) — почти наверняка
к февралю.

**Точка принятия решения — май 2027**, после сезона. Раньше данных не будет.
