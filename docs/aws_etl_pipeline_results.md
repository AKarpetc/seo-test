# Итоги Развертывания AWS S3 и ETL Pipeline

В этом документе зафиксированы результаты создания архитектуры загрузки и парсинга гигантских государственных данных США (Programmatic SEO).

## 1. Облачная S3-Инфраструктура
Мы создали **10 независимых бакетов** в AWS S3 для каждой ниши, чтобы избежать переполнения локального диска при работе с терабайтами данных. Названия бакетов автоматически добавлены в файл `.env`:
* `seo-pr-doctors-f40558`
* `seo-pr-broadband-f40558`
* `seo-pr-demographics-f40558`
* `seo-pr-energy-f40558`
* `seo-pr-executives-f40558`
* `seo-pr-trucking-f40558`
* `seo-pr-aircraft-f40558`
* `seo-pr-nutrition-f40558`
* `seo-pr-climate-f40558`
* `seo-pr-trademark-f40558`

*Безопасность:* На все бакеты применена политика **Block Public Access** — они защищены от публичного скачивания в интернете.

## 2. Архитектура Zero-Disk Streaming (`aws_data_ingestion.ts`)
Разработан скрипт, который решает проблему скачивания сверхтяжелых баз (5-10 ГБ). 
Вместо того, чтобы качать гигантский ZIP архив на локальный жесткий диск сервера, скрипт:
1. Автоматически находит актуальную ссылку на портале министерства (например, CMS NPPES).
2. Читает данные как сетевой поток (Stream).
3. Перенаправляет этот поток в AWS S3 (используя `@aws-sdk/lib-storage`), потребляя 0 байт на вашем жестком диске.

*Результат:* Успешно закачан реестр врачей NPPES (весом ~1.1 ГБ в архиве, 8+ ГБ без архива).

## 3. Мощный потоковый ETL-парсер (`parse_doctors.ts`)
Разработан конвейер, который переносит данные из AWS S3 в локальную PostgreSQL базу `seo_db` со сверхвысокой скоростью:
1. **Unzip на лету:** Скрипт тянет архив напрямую из S3 и распаковывает его в оперативной памяти (без сохранения на диск).
2. **CSV-streaming:** Распакованный текстовый файл сразу отправляется в CSV-парсер.
3. **ETL Трансформация:** 
   - Фильтрация пустых записей.
   - Слияние полей: извлечение NPI, Имени/Фамилии (или названия клиники), Адреса (Город, Штат, ZIP) и специализации.
   - Автоматическая генерация SEO-дружественного `slug` (например, `dr-david-wiebe-207x00000x-kearney-ne-1679576722`).
4. **Batch Insertion:** Вставка в PostgreSQL пачками по **10 000 строк** за одну транзакцию.

### Итоги первого тестирования базы Doctors
- **Размер партии:** Ограничение в 50 000 записей для теста.
- **Время выполнения:** ~15 секунд.
- **Статус:** 50 000 настоящих американских врачей и клиник успешно записаны в PostgreSQL. Архитектура полностью готова к заливке оставшихся 7 миллионов врачей и масштабированию на все остальные 9 баз данных.
